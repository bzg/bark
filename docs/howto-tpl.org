* 🐕 BARK --- Bug And Report Keeper

BARK monitors a mailbox and converts incoming emails into reports.
Subsequent emails in the same thread can update the status of that
report using predefined trigger keywords. Admins and maintainers can
update reports by writing directly to the monitored inbox, manage
roles, and receive periodic digest emails.

For admin and maintainers, see the full [[https://codeberg.org/bzg/bark/src/branch/main/docs/howto.org][BARK documentation]].

** Labels and trigger keywords

Subject labels create reports. Replies to these reports can update
them by using trigger keywords such as =applied.=, etc. Trigger keywords
should be placed at the beginning of the line and followed by a
punctuation mark (=.= =,= =;= =:=).

Here is a table of available labels and triggers for this BARK
instance:

| Type         | Subject labels                             | Acked              | Owned   | Closed               |
|--------------+--------------------------------------------+--------------------+---------+----------------------|
| bug          | =[BUG]= =[BUG topic]=                          | =Approved= =Confirmed= | =Handled= | =Canceled= =Fixed=       |
| patch        | =[PATCH]= =[PATCH topic]= =[PATCH topic v2 n/m]= | =Approved= =Reviewed=  | =Handled= | =Canceled= =Applied=     |
| request      | =[POLL]= =[FR]= =[TODO]= =[FR topic]=              | =Approved=           | =Handled= | =Canceled= =Done= =Closed= |
|--------------+--------------------------------------------+--------------------+---------+----------------------|
| announcement | =[ANN]= =[ANNOUNCEMENT]= =[ANN topic]=           |                    |         | =Canceled=             |
| release      | =[REL version]= =[REL topic version]=          |                    |         | =Canceled=             |
| change       | =[CHG version]= =[CHG topic version]=          |                    |         | =Canceled=             |

Topics can also be set using a colon-delimited prefix in the subject
after the label: =[BUG] parser: crash on empty input= sets the topic to
"parser". Multiple colons are supported: =[FR] auth: oauth: add refresh=
sets the topic to "auth: oauth".

** Priority trigger keywords

On top of trigger keywords to update the status of a report, users can
tell if a report is important (=Important.=) and/or urgent (=Urgent.=).

They cannot set the priority directly: priority is computed as the sum
of important (+1) and urgent (+2).

** Combining trigger keywords

You can combine several triggers in a single email:

#+begin_example
Confirmed.
Urgent.
Important.
#+end_example

** Searching via the web page

| Long form                   | Short | Explanation                                           |
|-----------------------------+-------+-------------------------------------------------------|
| from:me@example.org         | f:    | Reports from me@example.org                           |
| acked:me@example.org        | a:    | Reports acked by me@example.org                       |
| owned:me@example.org        | o:    | Reports owned by me@example.org                       |
| closed:me@example.org       | c:    | Reports closed by me@example.org                      |
| urgent:me@example.org       | u:    | Reports marked urgent by me@example.org               |
| important:me@example.org    | i:    | Reports marked important by me@example.org            |
| subject:match               | s:    | Reports matching subject                              |
| priority:[0-4]              | p:    | Reports matching priority level 0 to 4                |
| mid:<messageid>             | m:    | Report open with <messageid>                          |
| date:3d..                   | d:    | Reports from 3 days ago                               |
| date:2023-01-01..2023-12-31 | d:    | Reports from 2023-01-01 to 2023-12-31                 |
| match1 \vert match2             |       | Reports matching "match1" or "match2"                 |
| *                           |       | Wildcard for from/acked/owned/closed/urgent/important |
